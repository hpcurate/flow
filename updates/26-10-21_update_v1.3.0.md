## What was done

**The pill's own sizes (1).**
- Settings → Pill → **Width and height**: two sliders per size (the current one
  highlighted), reset per size. Bounds: S 120–480 × 20–64, M 300–1100 × 22–64,
  L 320–1200 × 28–80. The defaults are the old fixed sizes, so nothing moves
  until he drags.
- **The parts follow the height**: the time, buttons, tag, bars, visualiser,
  mark and start button size from it (clamped).
- **And give way as it narrows**, least important first. M: "break in…", the
  phase word, the tag, the visualiser, the bars. L: the song, the name, the bars,
  the visualiser. S: the visualiser, the bars. A large pill too low for two lines
  goes to one. This is read off the width at rest, so pointing at it (it grows)
  never reshuffles them.

**Dings (2).**
- A timer can ding every so often while it runs (≥ 10 s, shorter than the
  timer). Each ding is a soft note (unless the sound is off) and a bubble over
  the timer with the time left; docked beside the pill, the pill shows it too.
  No ding in the last 1.5 s: the end rings anyway.
- A bell marks the timers that ding. Each timer's "every" is in its edit form.
  Settings → Timers → **Ding every** is the default for new ones (empty = never,
  the default).

**A timer from CORE (3).** `FLOW.exe --flow-timer=15m --flow-timer-name=… [--flow-timer-every=5m]`
starts one, at launch or into the running FLOW (second instance). It turns
the timers on if they were off. CORE's "how long?" window uses it.

**Small:** the new-timer drop closes when FLOW loses focus, and when a row's
button is clicked (it could stay open over a collapsed field).
